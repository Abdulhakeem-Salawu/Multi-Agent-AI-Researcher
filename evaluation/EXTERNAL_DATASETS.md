# External benchmark integrations

This integration adds reusable loaders and deterministic scoring helpers for three public datasets. They remain separate from the internal, human-adjudicated ResearchBench schema because their annotation types and scoring meanings are not interchangeable.

## Tracks and label provenance

| Dataset | Track | Label type | What it measures |
|---|---|---|---|
| DeepResearch Bench II (DRB II) | Report rubrics | Expert-refined, atomic report rubrics; a judge returns 1, 0 or -1 | Information recall, analysis and presentation in generated research reports |
| FRAMES | Multi-hop QA | Dataset-provided answer and relevant Wikipedia article URLs | Multi-hop reasoning, answer correctness and retrieval |
| BrowseComp-Plus | Fixed-corpus retrieval and research | Human-verified evidence-document and gold-document labels | Finding evidence and answer-bearing documents in a fixed corpus |

Do not describe all three as human-annotated in the same sense. DRB II uses expert-authored reports and rubrics that were manually revised and expert-reviewed, but its per-run rubric scores are produced by an LLM judge. FRAMES provides gold answers and article references; its dataset card does not specify annotator-level adjudication. BrowseComp-Plus explicitly describes its evidence and gold document references as human-verified retrieval labels. None supplies our internal four-way claim-verification labels with evidence spans.

## Registry and adapters

The machine-readable registry is evaluation/external/registry.json. It records upstream locations, track purpose, annotation provenance, licence scope and corpus restrictions.

Python adapters are in evaluation/external/adapters.py:

- load_deepresearch_bench_ii_jsonl(path) reads the official tasks_and_rubrics.jsonl, keeps the task-level licence, rubric dimensions, blocked-source metadata and upstream IDs. CC BY 4.0 and CC0 are included by default. The two CC BY-NC 4.0 tasks are excluded by default; only set include_noncommercial=True for a non-commercial use after checking current rights.
- load_frames_tsv(path) reads the official test.tsv and preserves the upstream row index, question, answer, reasoning types and relevant article URLs. It does not fetch or store Wikipedia article bodies.
- load_browsecomp_plus_jsonl(path) consumes the de-obfuscated JSONL generated by the official upstream script. It retains query IDs, answer labels, evidence/gold/negative document IDs and URLs, but intentionally discards document text.

Each item uses ExternalBenchmarkItem, a thin wrapper that preserves labels in the dataset-specific annotations object. These items are not BenchmarkCase instances and cannot be passed to the internal ResearchBench scorer.

## Download the source files locally

External data belongs under data/external/, which is ignored by Git.

### DeepResearch Bench II

~~~bash
mkdir -p data/external/drb2
curl -L \
  https://raw.githubusercontent.com/imlrz/DeepResearch-Bench-II/main/tasks_and_rubrics.jsonl \
  -o data/external/drb2/tasks_and_rubrics.jsonl

research-external inspect deepresearch-bench-ii \
  --input data/external/drb2/tasks_and_rubrics.jsonl
~~~

The upstream repository states that the licence follows each source article. Its current task file includes 129 CC BY 4.0 tasks, two CC BY-NC 4.0 tasks (idx 26 and 110), and one CC0 task (idx 119). The adapter requires an explicit per-task licence and excludes non-commercial tasks by default. Preserve attribution and the exact source-file SHA-256 in each experiment record. Do not assume the upstream code licence overrides the per-task data licences.

### FRAMES

~~~bash
mkdir -p data/external/frames
curl -L \
  https://huggingface.co/datasets/google/frames-benchmark/resolve/main/test.tsv \
  -o data/external/frames/test.tsv

research-external inspect frames --input data/external/frames/test.tsv
~~~

The Hugging Face dataset card identifies FRAMES as Apache-2.0 and documents 824 multi-hop questions with gold answers and relevant Wikipedia links. This adapter stores the references only, not the linked Wikipedia content. Pin the dataset revision and record the input file SHA-256 before comparing model versions.

### BrowseComp-Plus

BrowseComp-Plus publishes an obfuscated query/evidence dataset and a separate fixed corpus. Use the official project repository and its scripts_build_index/decrypt_dataset.py workflow to prepare the local JSONL; do not implement an alternative decoder or publish a decrypted copy.

~~~bash
git clone https://github.com/texttron/BrowseComp-Plus.git external/BrowseComp-Plus
python -m pip install datasets
python external/BrowseComp-Plus/scripts_build_index/decrypt_dataset.py \
  --output data/external/browsecomp_plus_decrypted.jsonl

research-external inspect browsecomp-plus \
  --input data/external/browsecomp_plus_decrypted.jsonl
~~~

The upstream workflow may require Hugging Face authentication. Read its current instructions and terms before downloading. The query/evidence file contains 830 queries; the separate corpus contains about 100,195 documents. The adapter does not load that corpus and does not retain the full document text embedded in evidence records. The HF card has an MIT label, but crawled webpage content can remain subject to source-specific rights. Do not mirror or commit the corpus or decrypted benchmark files into this public repository. Use only an approved local or controlled evaluation environment, and check corpus rights before redistribution.

## Scoring helpers

evaluation/external/scoring.py provides:

- score_drb2_rubric_judgments(item, judgments): requires one score for every rubric ID and reports counts/rates for satisfied (1), not mentioned (0) and blocked-reference (-1) outcomes, overall and by dimension. It intentionally does not collapse the three categories into a single average.
- score_frames_answer(prediction, reference): normalized exact match and token F1. These are answer-level string metrics; they do not replace expert review of multi-hop reasoning.
- score_frames_retrieval(item, retrieved_article_urls, k=10): retrieval metrics against dataset-provided relevant article URLs.
- score_browsecomp_plus_retrieval(item, retrieved_docids, k=10): separate metrics against evidence and gold document IDs. Do not merge the two judgement sets; gold docs are a stricter subset with a distinct meaning.

These deterministic helpers score existing predictions/rankings only. They do not call an LLM, download data, infer labels, or set quality thresholds.

## Reproducibility and release rules

Before producing a scored comparison, record:

1. Dataset ID, official upstream URL, exact upstream commit/revision and split.
2. SHA-256 of each downloaded input file.
3. Adapter version (the Git commit containing this integration).
4. Licence scope and any per-task filtering.
5. Model, model version, prompt versions, retrieval configuration and scoring parameters.

The registry points to upstream main branches for discovery; it is not itself a frozen benchmark release. Pin immutable revisions before publishing a comparison. Do not commit downloaded datasets, decrypted BrowseComp-Plus queries, web document bodies, or retrieval indexes to this repository. These external tracks complement, but do not replace, the internal frozen snapshot and human adjudication workflow.
